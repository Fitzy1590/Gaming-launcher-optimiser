**Technical decisions**
- Decision logic goes in Core with a test; Windows/App only gather inputs and apply results. Every OS, hardware or game change writes a restore record first.
- Auto TDP is tuned from real session CSVs, one rule at a time, test first (see the `auto-tdp-log-review` skill). Heat is judged over a window, never one reading; FPS above the cap is not headroom; a low 1% low alone is a hitch, not a need for watts.
- Emulation Hub: sources stay `Verified = false` until checked against the emulator's own GitHub releases; config edits are key-level and only touch keys that already exist; unknown emulator version = preview only; update/DLC info is local only (no online catalogue); no ROM, BIOS or key content anywhere.
- Every push to `main` is a release (`v0.3.<run>`); there is no manual version or tag.
- Cloud sessions: the .NET 10 SDK comes from Ubuntu's `dotnet-sdk-10.0` package (Microsoft's download host is blocked there). A setup script on the Fitz-TV cloud environment installs it when this repository is present. Not yet proven on a fresh session; if `dotnet` is missing, run `apt-get update && apt-get install -y dotnet-sdk-10.0`.
- Procedures live in skills, not in `CLAUDE.md`, so everyday sessions stay small.
